A gate run, unedited

EvalForge is a regression gate for RAG and agent answers: it keeps the cases where an answer looked right but cited the wrong evidence, and fails the build when a change brings that error back. This page is one real run of its bundled suite, generated by the tool and published without retouching — including the case that failed.

What produced it

pip install -e .
evalforge eval example_suites/rag_basic.yaml -b mock -f html -o reports

The backend is deterministic and offline: no provider key, no network. The suite file hashes to c02cc63b… and has not changed since the repository's initial commit, so the same input produces the same report. (b707e5b1… is the portfolio evidence bundle, a different artifact.)

The case that failed

fact-003Speed of light0.06 / 0.60 the mock backend's canned answer does not meet the case's semantic threshold

The failure stays on the page because a gate that only shows green is not a gate. It is a property of the fixture, not of a model: the mock returns fixed text, and this case asks for a figure it does not contain. A real run against a provider would show the same report with that case judged on the actual answer.

What the report shows

Per case: the question, the answer, the trusted passage, the check that ran and the score it produced — the same structure that lets a release decision be inspected after the fact. Pass, fail and indeterminate are separate exits, so a run that cannot be judged does not silently pass.
